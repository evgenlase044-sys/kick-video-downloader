# Оставшиеся правки после PR #1–#5

Состояние `main` после мерджа PR #5. Отсортировано по влиянию на итоговый ролик.
Каждый пункт: что не так, где, как чинить, как проверить.

## 0. Сделать один раз руками (5 минут)
1. **Вшить патчи в исходники.** Сейчас фиксы `server.py`/`editor.js`/`index.html` живут только при запуске через
   `studio_server.py`. Запусти `python -m studio.patching --write`, проверь `git diff`, закоммить.
   Потом `python -m studio.patching` должен показывать только `already`.
2. **Включить CI.** У токена автоматизации не было права `workflow`, поэтому файлы лежат в `tools/github-workflows/`.
   Перенеси `ci.yml` (и при желании `fold-patches.yml`) в `.github/workflows/`.
3. **Прогнать проверки локально:** `bash tools/ci_check.sh`. Все тесты PR #5 написаны под CI и частично не запускались
   в среде, где делались правки (нет fastapi / исходников `server.py`), поэтому первый прогон обязателен.

## 1. Один рендер для текста (главный разрыв превью ↔ файл) — P0
* **Проблема:** превью рисует текст новым `canvasText.js` (страницы, караоке, 3D), экспорт по-прежнему рисует ASS/libass в `server.py`
  со своими стилями и метриками. После PR #5 разница стала заметнее (в превью страницы и караоке, в файле нет).
* **Как:** гибрид из аудита. В браузере рендерить текстовый слой тем же `drawCue()` в `OffscreenCanvas` с альфой
  → слать RGBA (или PNG-секвенцию / `qtrle`) на новый WS `/ws/overlay/{job}` → в `_export_layered_clip()` добавить
  `overlay` поверх видео. ASS оставить фолбэком.
* **Проверка:** экспорт 3 кадров → сравнить с `canvas.toDataURL()` превью, разница < 2% пикселей в зоне текста.

## 2. Экспорт (`server.py`) — P0/P1
* **`-ss` перед `-i` в `_export_layered_clip()`** не проверен (аудит не смог прочитать тело). Если обрезка фильтрами —
  20 с из 4-часового VOD декодирует весь файл. Проверить первым делом.
* **NVENC/битрейты платформ в основном экспорте.** `studio/ffmpeg_caps.h264_args()` используется только в WS-рендере;
  `export-pack` всё ещё `libx264 medium crf15`. Заменить аргументы кодека на `h264_args(fps)`.
* **30 fps для разговорных клипов** (шаблон «История»/«Чистый» уже задаёт `fps: 30`, экспорт это поле пока не читает).
* **8-бит грейд:** `LUT → cas → format=gbrp` → текст → `yuv420p` даёт бандинг. Перейти на `gbrpf32le` (или 10 бит) до финального `format=yuv420p` с дизером.
* **`setparams` не конвертирует цвет:** заменить на явный `zscale=matrixin=...:matrix=709` / `colorspace`.
* **Два аудиопути:** легаси без слоёв использует однопроходный `loudnorm=I=-14:TP=-1.5`; привести к двухпроходному + лимитер.
* **ASS-тайминг:** квантование кадров → сантисекунды даёт джиттер word-pop; уйдёт вместе с п.1.
* **Отдельный грейд facecam/геймплей** и полный `grade.js` (CDL, skinProtect, split-toning): в экспорте только LUT.
  Порядок из аудита: денойз хромы → экспозиция/ББ → контраст → skin protect → LUT 30–60% → шарп.
* **Motion blur на зумах/тексте:** суб-кадровое накопление (4–8 сэмплов) только на интервалах движения.
* **Lens в экспорте статичный** (`lenscorrection` на интервале). Анимировать k1 через `sendcmd` или рендерить через canvas-слой.

## 3. Фронтенд (`web/editor.js`) — P1
* `removeTrack()` пересчитывает и сохраняет проект **до** подтверждения; перетаскивание клипа не вызывает `saveProject()`.
* Backspace без `preventDefault()` вне полей ввода.
* SSE `/api/progress` без переподключения (очередь экспорта уже переподключается).
* Аудио-мастер-клок написан, но не подключён: превью синхронизируется по плейхеду.
* При удалении медиа вызывать `canvasMonitor.dropMedia(filename)` (метод добавлен в PR #5) и `decoder.drop()`.
* Хуки для новых возможностей превью: `hooks.faceAnchor(clip, t)` (центр трекера лица для зума) и
  `window.studioSeek(t)` / `window.studioTranscriptWords` для панели моментов (сейчас панель ищет `<video>` сама,
  без слов транскрипта сигнал речи не используется).
* Событие `studio:template-plan` (план эффектов шаблона) пока никто не слушает: добавить обработчик, который
  создаёт fx на таймлайне и применяет раскладку/стиль/грейд шаблона.
* `hot_words`: заменить эвристику «самое длинное слово» на имена/числа/маты/повороты (или флаг от LLM) и включить по умолчанию.
* Emoji/стикеры: системы нет.
* Браузерный экспортёр (`core/render/exporter.js`) заморожен: удалить файл или довести до WebCodecs `VideoEncoder`
  (сейчас `getImageData` 1080×1920@60 в главном потоке ~187 МБ/с).

## 4. Скачивание — P1/P2
* fMP4 / BYTERANGE / зашифрованные плейлисты теперь дают понятную ошибку, но не скачиваются.
* Kick-извлечение через regex по HTML: перейти на `api/v2/video/{uuid}` и `api/v1/channels/{slug}` с фолбэком на HTML.
* Размер — оценка по 15 HEAD-запросам (помечено `is_estimate`), не точный.
* Демуксер: fMP4/TS только с явной ошибкой; VFR-длительности по stts уже учитываются.
* **Запись чата во время эфира** (Kick не всегда хранит чат VOD): отдельный процесс по Pusher/WebSocket Kick → JSONL
  `{t, user, text}` в `downloads/`, этот файл уже принимает `/api/studio/moments` (`chat_file`).

## 5. Безопасность — P1
* Всё закрыто только в `studio_server.py`. Прямой `python server.py` = старый сервер (0.0.0.0?, без токена,
  `/api/shutdown` открыт). После п.0.1 добавить в `server.py` `if __name__ == "__main__"` → запуск `studio_server.main()`.
* `/api/media/import` допускает любой медиафайл с диска по пути (так задумано для импорта); при желании ограничить
  папками пользователя (Видео/Загрузки/Рабочий стол).
