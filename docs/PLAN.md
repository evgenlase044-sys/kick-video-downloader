## 0. Продуктовые принципы (обязательны для всех разделов ниже)

1. **Ручной инструмент, а не «одна кнопка».** Цель — максимально быстро сделать из одного стрима **несколько** вирусных нарезок эффективными ручными инструментами: хоткеи, пресеты, шаблоны, «эффект в точке плейхеда», очередь экспорта. Никаких автопилотов, которые решают за пользователя.
2. **Нейро — только там, где руками долго и бессмысленно: субтитры.** ASR делается **только через Groq API** (`whisper-large-v3-turbo` / `whisper-large-v3`). **Никаких локальных моделей** (faster‑whisper, WhisperX, torch, onnxruntime, MediaPipe, RVM, YuNet, Real‑ESRGAN и т.п.) — ни в зависимостях, ни в планах.
3. **Никаких «умных» фич сверх субтитров.** Удалено из плана: автодетект лица/вебки, авто‑регионы, бит/онсет‑детект и «кейфреймы под бит», LLM‑hot‑words, авто‑эффекты на пиках громкости, «Сделать Short одним кликом», сегментация человека, AI‑апскейл.
4. **Область выбирается руками на предпросмотре.** Лицо/вебка/контент — простым ручным инструментом рамки прямо на мониторе, с пресетами на канал.
5. **Трекинг объекта есть, но с зоной.** Пользователь задаёт *что* трекать (рамка цели) и *где* разрешено искать (рамка зоны). Трекер физически не может выйти за зону. Трекер — классическое CV (template matching / CSRT), не нейросеть.
6. **Опенсорс, некоммерческий.** Каждая зависимость и каждый ассет (шрифты, SFX, LUT) — с совместимой лицензией и явной атрибуцией. Никаких проприетарных SDK/шрифтов/плагинов. См. §19.
7. **WYSIWYG.** Превью и экспорт рисует один и тот же код; что видишь — то и получишь, кадр в кадр.
8. **Look «вирусного шортса».** Отдельный модуль **Lens & Detail** (искажение линзы, bulge, хроматическая аберрация, перерезкость, смаз) — ручные параметры с кейфреймами и пресетами. См. §13.

## 1. TL;DR

1. **Первопричина плохого качества одна:** анимация и типографика делаются языком субтитров (ASS/libass), эффекты — цепочками FFmpeg, превью — третьим несвязанным рендерером (DOM+CSS). Три рендерера никогда не совпадут, у libass потолок (нет пружин, motion blur, свечения от маски, раскладки слова в фразе, 4:4:4).
2. **Цель:** один декларативный формат сцены (`Composition JSON`) + **один WebGL2‑рендерер в Electron**, который работает и как живое превью, и как экспорт (кадры → `server.py` → x264).
3. **До переписывания** — пакет хотфиксов (Фаза 0), который убирает самые заметные дефекты: двойной текст, разъезд букв, пятна glow, «тень без смещения», грязные цветные края текста, скачок зума на шейке, мыло от `hqdn3d`, неверный кроп при леттербоксе, склеенные «цель» и «зона» трекера.
4. **Мыло — ещё и от источника 720p.** 9:16 из 1280×720 = полоса 405×720 → ×2.67. Качать **source/1080p60** по умолчанию (608×1080 → ×1.78).
5. **Субтитры — Groq, но надёжно:** чанкинг с перекрытием под лимит 25 МБ, ретраи 429/5xx, `language`, словарь канала в `prompt`, фильтр галлюцинаций Whisper, кэш по хэшу. Локальных моделей нет и не будет.
6. **Скорость работы важнее автоматики:** маркеры во время просмотра VOD, пресеты раскладки на канал, стиль‑пакеты, «эффект в плейхеде» одной клавишей, пакетный экспорт в фоне. KPI: **3 готовых шортса из 2‑часового VOD ≤ 15 минут ручной работы**.
7. **Лицензии — блокер релиза:** нет `LICENSE`, `package.json` = ISC, лендинг = MIT, у шрифтов нет OFL‑файлов, происхождение `sfx/*.mp3` и `tv_grade.cube` неизвестно. Всё закрывается в §19.

## 4. Первопричины (сводный реестр, с привязкой к коду)

Подробные доказательства и статус каждой — в `VERIFICATION.md`.

### 4.1. Архитектурные (RC)
- **RC1 — два источника текста (D1).** `ExportClipItem` одновременно принимает `subtitles` (→ `build_tv_subtitles_ass`) и `text_items` (→ `build_text_elements_ass`), дедупа нет. `editor.js`: `wordsToTimelineClips` / `#applySubtitlesToTimelineBtn` кладут фразы на дорожку текста, а стиль Shorts параллельно шлёт те же субтитры в `subtitles`.
- **RC2 — чужие метрики букв (D2).** `_letter_positions()`/`_letter_widths()` мерят глифы `fontTools` по одному файлу, а рисует libass через fontconfig (для кириллицы может подставить другой). Нет глифа → `0.62·size`. Каждая буква — отдельный Dialogue с `\pos` и своим pop → кернинг теряется. `N` из `\N` рисуется как буква. `spacing` до 30 px на букву.
- **RC3 — glow живёт отдельно от текста (D3).** Glow‑слои без `\fad`, у Main `\fad(15,…)`; `wide_b = max(8, size·0.14·gk)`.
- **RC4 — раскладка «верх/низ» по умолчанию (D4)** при пустых `crop_box`/`bg_box`: `top_h = out_h·0.45`. Пикер `#pickSolo` с `object-fit: contain` нормализует по контейнеру, а сервер трактует как доли исходника → рамка смещается при леттербоксе.
- **RC5 — источник и масштабирование (D5).** 720p; `hqdn3d=1.2:1.2:5:5` перед LUT; многократные `scale`; всё в 8‑бит `yuv420p` в гамме.
- **RC6 — грейд‑косметика (D6).** `hqdn3d → lut3d(17³, tetrahedral) → eq(1.05/1.10/0.01) → cas 0.30 → yuv420p`; дефолт `color_grade` расходится (`none` на сервере / `tv` в клиенте).
- **RC7 — эффекты FFmpeg‑ом (D7).** `shake` = `crop` по синусу + `scale` (края, мыло, нет motion blur); `flash` = `blend=addition` (клиппинг); нет зума, смаза, линзы, RGB‑split, спидрампа.
- **RC8 — превью отдельный мир (D8).** `#studioVideoPlayer` + скрытый `#tvPreview` (3 `<video>`) + `#subtitlesMonitorOverlay`; `state.aspectRatio = "16:9"` не связан с `state.clipper.format`; CSS `@keyframes` по wall‑clock; `activeVideoLayers()` ≤ 2; рассинхрон до 120 мс; шаг кадра 1/30 при 60 fps.
- **RC9 — Rust‑движок `engine/` не вызывается** и содержит баги (декодер без `crop`, нет нормализации FPS, `draw_emoji` в угол, паника на пустом `colors`, абсолютные пути).
- **RC10 — техдолг.** Два `_sfx_maybe_file`; текст не экранируется для ASS; расходящиеся дефолты стиля/шрифта/glow/грейда; перезапись `fonts/fonts.conf` на старте; `_source_has_audio → True` при ошибке; трим `-ss … -c copy` по ключевым кадрам; двойное квантование времени ASS (1/60 → 1/100, дрожь ±10 мс).

## 5. Целевая архитектура

```
┌──────────────────── Electron (main.js) ────────────────────┐
│ UI (editor)  ──►  Composition JSON (единый стейт проекта)   │
│                         │                                   │
│         ┌───────────────┴───────────────┐                   │
│         ▼                               ▼                   │
│ PREVIEW: renderFrame()          EXPORT: renderFrame()       │
│ WebGL2, realtime, от mediaTime  тот же код, offscreen,      │
│ (P0: <video>→canvas; P1: WebCodecs)  60 fps, motion blur    │
│                                        │ YUV420 кадры (PBO) │
└────────────────────────────────────────┼────────────────────┘
                                         ▼  WebSocket localhost
            server.py (FastAPI): ffmpeg rawvideo → libx264 slow CRF16 + аудио‑микс
server.py также: скачивание/ingest, Groq ASR, трекинг (OpenCV, CPU),
                 прокси‑файлы, волна/громкость (для отображения), очередь экспорта.
Никаких локальных нейросетей.
```

Почему так: один рендерер = WYSIWYG по определению; Chromium уже внутри Electron (HarfBuzz, кириллица, цветные эмодзи); WebGL2‑шейдеры дают все эффекты вирусных эдитов; каждое свойство — чистая функция от времени (детерминизм, повторяемый экспорт).

## 6. Фаза 0 — хотфиксы в текущем коде (3–5 дней)

**0a. Гигиена (1 день)**
- N16: `/api/version`, `main.js` сверяет и перезапускает `server.py`. Первый шаг любой проверки — убедиться, что запущена эта копия.
- N1–N7, N18, экранирование ASS‑текста.

**0b. Экспорт и текст (1–2 дня)**
- **H1 — один источник субтитров.** `subtitle_mode: "timeline" | "generated" | "none"`. Сервер отвечает **422**, если одновременно есть ASR‑клипы с `words` в `text_items` и непустой `subtitles`. UI: «На слой титров» переводит режим в `timeline` и очищает `subtitles`.
- **H2 — печать одной строкой.** Ветка `anim_in == "type"`: один Dialogue на строку, скрытые буквы `{\alpha&HFF&}` + `{\t(t_i,t_i+1,\alpha&H00&)}` перед каждой; `spacing` по умолчанию 0, максимум 6 px.
- **H3 — шрифты с кириллицей.** На старте проверка cmap (U+0410–U+044F, U+0401, U+0451) через `fontTools`; в UI только прошедшие. Добавить OFL‑шрифты: **Montserrat Black Italic / ExtraBold Italic**, **Inter Tight Black Italic**, **Unbounded Black**, **Manrope ExtraBold**. `Impact`/`Arial Black` (проприетарные) — не бандлить, убрать из дефолтов.
- **H4 — glow не раньше текста.** Glow с `\alpha&HFF&` → `\t(60,160,\alpha&H80&)`; `wide_b ≤ 0.08·size`, `core_b ≤ 0.04·size`.

## 7. Быстрый ручной пайплайн «стрим → несколько нарезок»

### 7.1. Проход по VOD
- Просмотр VOD на 1.5×/2× (J/K/L‑шаттл), **M** — маркер в текущей точке (опционально с заметкой, Shift+M). Маркеры видны на обзорной полосе вместе с **волной громкости** (чисто отображение RMS, без автоматических решений).
- Из маркера **Enter** → регион‑нарезка с дефолтным окном (настраивается, по умолчанию −20 с / +10 с), I/O для точной правки, снап к маркерам/границам слов.
- Прокси 960×540 GOP 10 для мгновенного скраба; экспорт — всегда из оригинала.

### 7.2. Шаблоны и пресеты (всё ручное, сохраняемое)
- **Пресет канала:** рамка вебки, рамка контента, раскладка, стиль‑пакет, словарь для Groq‑prompt. Применяется к новой нарезке этого канала одним нажатием (или автоматически по имени канала — это подстановка сохранённого, а не ИИ).
- **Стиль‑пакет** (один JSON): шрифт, палитра, аниматоры in/out/idle, glow/stroke/shadow, грейд, пресет Lens & Detail, набор SFX. Общий для карточек UI, превью и рендера.
- Копировать/вставить атрибуты между нарезками (Ctrl+Alt+C / Ctrl+Alt+V): раскладка, стиль, грейд, эффекты — выборочно.

### 7.3. «Эффект в плейхеде» — главный ускоритель
Одна клавиша ставит эффект с дефолтными параметрами ровно в текущий кадр, дальше правится в инспекторе:

| Клавиша | Эффект (дефолт) |
|---|---|
| Z | Zoom punch 1→1.15, пружина 12%/220 мс + радиальный смаз |
| L | **Lens punch** (§13.3): зум + бочка + CA, 250 мс |
| F | Flash screen белый 180 мс (Shift+F — цвет по кругу) |
| X | Shake 14 px, 350 мс, с motion blur |
| B | Threshold hit 2 кадра |
| W | Whip‑переход на ближайшем резе |
| R | Speed ramp 0.35× → 1.8× вокруг плейхеда |
| E | Стоп‑кадр + зум 0.6 с |
| 1–9 | цвет палитры для выбранного слова субтитров |
| H | пометить выбранное слово как hot (`slam` + цвет акцента) |
| C | инструмент рамки (кроп/область) · **T** — трекинг выбранного слоя |

Каждый эффект несёт **дефолтный SFX** из `sfx/` (whoosh на whip, impact на slam/flash, click на `char_type`), отключаемый.

### 7.4. Очередь экспорта
Пакетный экспорт всех готовых нарезок в фоне, пока правится следующая; шаблон имени файла (`{channel}_{date}_{n}_{title}`); прогресс/отмена через SSE.

type Anim<T> = T | { k: Array<[t: number, v: T, ease?: Ease]> } | { spring: {O:number, Ts:number}, from: T, to: T, at: number };

### 8.3. Одна функция времени
```ts
function mapTime(layer, t) {                       // timeline → локальное → исходник
  const local = t - layer.time.in;
  const src = layer.time.speed ? layer.time.srcIn + integrateSpeed(layer.time.speed, local)
                               : layer.time.srcIn + local;
  return { local, src };
}
```
Используют декодер, текст (обратная проекция слов), аудио (`atempo` сегментами), трек, экспорт. Удаляются `subs_in_output_time` и `_remap_subtitles_for_segments`. Слово на склейке принадлежит сегменту, где лежит его **середина**; концы обрезаются; слово < 2 кадров выкидывается.

### 8.4. Инвариант текста
`subtitle_mode` (§6 H1); 422 на конфликт — двойной текст закрыт контрактом.

## 9. Ручной выбор области на предпросмотре

### 9.1. Поведение
- **C** — инструмент рамки поверх **монитора** (не отдельного солo‑плеера): рамка рисуется по исходнику, соседняя панель сразу показывает результат в 9:16.
- Режимы пропорций: свободно / 9:16 / 1:1 / 4:5 / 16:9 / «как слот раскладки» (по умолчанию — пропорция слота, куда пойдёт кроп).
- Ручки по углам и сторонам, перетаскивание, Shift — симметрично от центра, Alt — без снапа; стрелки — сдвиг на 1 px исходника, Shift+стрелки — 10 px.
- **Снап** к краям кадра и к краям ранее сохранённой рамки вебки.
- Числовые поля x/y/w/h в px исходника (для точной подгонки и копирования).
- **Кейфреймы кропа** (ручной рефрейм): ◆ в текущем кадре, интерполяция easeInOut; опция «следовать за треком» (§10.5).
- Оверлей safe‑area Shorts/TikTok поверх 9:16 результата.

### 9.2. Координаты без смещения (фикс RC4)
```js
function contentRect(el, vw, vh) {                  // где реально лежит видео при object-fit: contain
  const r = el.getBoundingClientRect(), s = Math.min(r.width / vw, r.height / vh);
  const w = vw * s, h = vh * s;
  return { x: r.left + (r.width - w) / 2, y: r.top + (r.height - h) / 2, w, h };
}
const toSource = (px, py, cr) => ({ x: clamp01((px - cr.x) / cr.w), y: clamp01((py - cr.y) / cr.h) });
```
В P0/P1 монитор — canvas с известной матрицей «канва ↔ исходник», поэтому преобразование точное по построению.

### 9.3. Раскладки
`cam_top_content_bottom`, `fullscreen` (один кроп), `content_full_cam_pip`, `blur_fill` (размытая подложка + вписанный кадр), `cam_only`. Дефолт без рамок — `fullscreen` по центру, **не** «верх/низ исходника». Слот вебки на верхних дорожках явно помечается иконкой «на весь кадр / PiP» (иначе клип на «Оверлей/Вебка» перекрывает кадр целиком).

### 9.4. Пресеты области на канал
`presets/channels/<channel>.json`: `cam_box`, `content_box`, `layout`, `style_pack`, `asr_prompt`. У стримера вебка почти всегда на одном месте — рамка ставится один раз, дальше применяется ко всем нарезкам (кнопка «Применить пресет канала», хоткей P). Если стример сменил сцену — поправил и «Сохранить как пресет».

## 10. Трекинг объекта с ограничением области

### 10.1. UX
1. Выбрать слой → **T** → нарисовать **рамку цели** (сплошная) вокруг объекта в текущем кадре.
2. Рамка **зоны** (пунктир) по умолчанию = цель ×3, клиппинг к кадру; тянется ручками; можно задать ключами (зона двигается вместе со сценой).
3. Направление: вперёд / назад / в обе стороны от текущего кадра до границ региона.
4. Результат — путь на мониторе + полоса уверенности на таймлайне (зелёный/жёлтый/красный). Красные участки — «потерян»: трекер держит последнюю позицию и ждёт руки.
5. Правка: в любом кадре подвинуть рамку → ручной ключ ◆ → **перетрекинг только участка** до соседнего ручного ключа (Enter). Ручные ключи — жёсткие ограничения.
6. Применение трека: follow‑cam кропа, PiP, привязка текста/никтега/стикера, центр bulge/lens (§13), центр zoom punch.

### 10.2. API
```python
class Box(BaseModel):  x: float; y: float; w: float; h: float          # 0..1, space=source
class ZoneKey(Box):    t: float
class TrackRequest(BaseModel):
    filename: str
    t_from: float; t_to: float; t_anchor: float                           # anchor = кадр с рамкой цели
    target: Box
    zone: Optional[Box] = None                                            # статичная зона
    zone_keys: Optional[List[ZoneKey]] = None                             # или анимированная
    manual_keys: List[ZoneKey] = []                                       # жёсткие ключи пользователя
    mode: Literal["ncc", "csrt"] = "ncc"
    fps: float = 0                                                        # 0 = родной FPS региона
    analysis_width: int = 960
    scale_search: bool = False                                            # мультимасштаб 0.97/1/1.03
    min_conf: float = 0.55
# ответ (SSE прогресс + итог): keys: [{t,x,y,w,h,conf,lost,manual}]
```

### 10.3. Алгоритм `ncc` (по умолчанию, детерминированный, OpenCV `matchTemplate`, Apache‑2.0)
- Кадры: `ffmpeg -ss … -t … -vf fps=<fps>,scale=<analysis_width>:-2,format=gray` в pipe (без временных JPEG).
- Признак: яркость + (опционально) модуль Собеля — устойчивее к смене освещения.
- Окно поиска кадра `W_n = (prev_center ± k·size) ∩ ZONE_n`, `k = 1.5`. **Зона — жёсткий предел**: центр и сама рамка клампятся так, чтобы рамка целиком лежала в зоне.
- `TM_CCOEFF_NORMED`; **субпиксельный пик** параболой по 3×3 вокруг максимума.
- Мультимасштаб (если включён): лучший из {0.97, 1, 1.03}, масштаб сглаживается.
- Обновление шаблона: `T = 0.9·T + 0.1·patch` при `conf > 0.8` **и** `NCC(T0, patch) > 0.5` (якорь к исходному шаблону против дрейфа).
- Потеря: `conf < min_conf` 3 кадра подряд → `lost=true`, позиция удерживается; при `conf > min_conf+0.1` 3 кадра — восстановление.
- Сглаживание выхода: **One Euro** (`minCutoff 1.0 Гц`, `beta 0.02`, `dCutoff 1.0`), ручные ключи не сглаживаются.
- Режим `csrt` — `cv2.TrackerCSRT` (opencv‑contrib, Apache‑2.0) на кадрах, **обрезанных по зоне**: трекер физически видит только зону; координаты переводятся обратно. Для объектов, которые меняют вид (поворот головы).
- Никаких нейросетевых трекеров.

### 10.4. Хранение и применение
- Трек живёт в `composition.tracks[id]` (исходное время), слои ссылаются на него. Интерполяция между ключами — кубическая Эрмита по центру и линейная по размеру.
- Экспорт в переходный период — `_build_track_expr` (кусочно‑линейные выражения FFmpeg); в рендерере — `trackAt(track, srcTime)`.

### 10.5. Follow‑cam (виртуальная камера по треку)
`cropCenter_n = cropCenter_{n-1} + clamp(dead(target_n − cropCenter_{n-1}, deadZone), ±maxSpeed·dt)`, затем критически демпфированная пружина (Ts 0.35 с). Кроп всегда клампится к кадру исходника. Параметры — ползунки «мёртвая зона», «макс. скорость», «плавность».

## 11. Субтитры: только Groq API

### 11.1. Запрос
- Endpoint `https://api.groq.com/openai/v1/audio/transcriptions`, ключ `GROQ_API_KEY` (из `.env` или поля в настройках; в репо не хранится; каждый пользователь — со своим ключом).
- Модель: `whisper-large-v3-turbo` (по умолчанию, быстрее/дешевле) или `whisper-large-v3` (точнее; переключатель «Точнее»).
- `response_format=verbose_json`, `timestamp_granularities[]=word` **и** `segment` (segment нужен ради `no_speech_prob`/`avg_logprob` для фильтра галлюцинаций), `temperature=0`, `language` из настроек (по умолчанию `ru`, опция «авто»), `prompt` ≤ 224 токенов = словарь канала (ники, сленг, названия).
- Аудио: `-vn -ac 1 -ar 16000 -c:a flac` (без потерь, Groq всё равно даунсэмплит до 16 кГц моно).

### 11.2. Надёжность
- **Лимит размера**: free — 25 МБ, dev — 100 МБ. Если файл > 24 МБ — чанки по 600 с с перекрытием 5 с; слова из перекрытия берутся из того чанка, где середина слова дальше от края; смещение времени — `chunk_start`.
- **Ретраи**: 429/5xx/таймаут → экспоненциальная задержка 2/4/8/16 с (или `Retry-After`), максимум 5 попыток; понятное сообщение в UI.
- **Кэш**: `downloads/.cache/asr/<sha1(file,start,end,model,language,prompt)>.json` — повторная транскрипция того же куска бесплатна и мгновенна.
- **Фильтр галлюцинаций Whisper**: выкидывать сегменты с `no_speech_prob > 0.6 && avg_logprob < −1.0`, а также известные фразы‑призраки на тишине («Продолжение следует…», «Субтитры сделал …», «Спасибо за просмотр», «Редактор субтитров …») — список редактируемый.
- Нет ключа/нет сети → кнопка субтитров неактивна с подсказкой; ручной текст работает всегда.

### 11.3. Постобработка (детерминированная)
- Экраны по 1–4 слова: пауза > 250–350 мс, ≤ 1.5 с, знаки препинания; максимум 2 строки.
- Опции: «ё», КАПС, удаление слов‑паразитов по списку, маскирование мата по списку (`б**`).
- Времена слов → `mapTime()`.

### 11.4. Ручное редактирование (главное)
- Редактор слов: правка текста не ломает тайминги; разделить/склеить экран (Ctrl+K / Ctrl+J); перетаскивание границ слов на таймлайне с волной под ними.
- Клик по слову → цвет (1–9) / hot (H) / ремарка‑печать `*…*` (вставка вручную).
- Никаких LLM для выбора слов или переписывания текста.

## 12. Текстовый движок уровня After Effects

### 12.1. Шрифты
```js
const face = new FontFace("Montserrat", "url(/api/fonts/Montserrat-BlackItalic.ttf)", { weight: "900", style: "italic" });
await face.load(); document.fonts.add(face);            // в воркере: self.fonts.add(face)
if (!document.fonts.check('italic 900 100px "Montserrat"', "ЁЖЯ")) throw new Error("font not ready");
```
Экспорт не стартует, пока шрифты сцены не загружены. Нужны настоящие курсивные начертания (синтетический shear ломает bbox и кернинг).

### 12.2. Сегментация
`Intl.Segmenter("ru", {granularity:"grapheme"})` для букв (эмодзи с ZWJ, «й/ё» из двух кодпоинтов — одна единица), `"word"` для слов. Переносы — явные токены.

### 12.3. Раскладка с кернингом
```js
ctx.font = 'italic 900 120px "Montserrat"'; ctx.fontKerning = "normal"; ctx.letterSpacing = `${tracking}px`;
const g = [...seg.segment(line)].map(s => s.segment);
let acc = "", xs = [];
for (const ch of g) { xs.push(ctx.measureText(acc).width); acc += ch; }   // x начала каждой графемы
const lineW = ctx.measureText(acc).width;
```
Кэш по `(font,size,text)`. Перенос: максимум 2 строки, ширина ≤ 0.86·W, выбирается разрыв с минимальным `max(w1,w2)`; не влезает — кегль −4% до `minSize`, затем разбиение экрана. Safe‑area (1080×1920): верх 0–220, низ 1520–1920, правый край 950–1080 в нижней половине; субтитры по умолчанию `y = 0.64–0.70·H`.

### 12.4. Растеризация и пассы
- Растр строки один раз на уникальное состояние в масштабе `S = maxAnimatedScale · renderScale · 2`; mipmaps, `LINEAR_MIPMAP_LINEAR`. Паддинг = stroke + glowRadius + |shadowOffset| + shear·ascent.
- Каждая графема — отдельный квад из общего растра (кернинг сохраняется), инстансинг атрибутов `translate, scale, rot, opacity, blur, colorMix, glowBoost`.
- Пассы: (1) fill → FBO RGBA16F premultiplied; (2) **stroke через SDF** (jump‑flood, `a = smoothstep(r+0.5, r−0.5, d)`); (3) **glow от цветного слоя** dual‑Kawase, радиусы 0.15em/0.45em, веса 0.85/0.45, add в линейном; (4) drop shadow σ 0.08em, смещение (0, 0.06em), 60–70%; (5) extrude 6–12 копий (MrBeast).
- `glowAlpha_i = opacity_i^1.5 · glowAmount · glowBoost_i` — glow физически не может появиться раньше буквы.

### 12.5. Пружина
```js
function springParams(O, Ts) { const L = Math.log(O); const z = -L / Math.sqrt(Math.PI**2 + L*L); return { z, w0: 4 / (z * Ts) }; }
function spring(t, { z, w0, v0 = 0 }) {             // [x, dx/dt], 0 → 1
  if (t <= 0) return [0, v0];
  const x0 = -1;
  if (z < 1) {
    const wd = w0 * Math.sqrt(1 - z*z), e = Math.exp(-z*w0*t);
    const A = x0, B = (v0 + z*w0*x0) / wd, c = Math.cos(wd*t), s = Math.sin(wd*t);
    return [1 + e*(A*c + B*s), e*((-z*w0)*(A*c + B*s) + (-A*wd*s + B*wd*c))];
  }
  const e = Math.exp(-w0*t), B = v0 + w0*x0;
  return [1 + e*(x0 + B*t), e*(B - w0*(x0 + B*t))];
}
```
Эталон pop: 18%/300 мс → ζ=0.479, ω₀=27.8 рад/с; `slam` 8%/200 мс; `bounce` 30%/450 мс. Безье — Ньютон 4–6 итераций + бисекция (как `UnitBezier` Chromium). Easy Ease `(0.33,0,0.67,1)`, «snap» `(0.16,1,0.3,1)`.

## 13. Lens & Detail — look «искажения» вирусных шортсов

> Референс пользователя не дошёл. На вирусных шортсах этот look почти всегда — комбинация из: **искажения линзы (бочка/fisheye, «Optics Compensation»)**, **bulge/pinch в точке (CC Lens/Bulge)**, **радиальной хроматической аберрации**, **перерезкости (unsharp малого радиуса + high‑pass clarity, «4K look»)**, **волнового/теплового искажения**, **радиального/направленного смаза** на зум‑панче. Модуль даёт все компоненты ручными ползунками с кейфреймами; пресет, повторяющий конкретное видео, собирается после повторной отправки файла.

### 13.1. Компоненты (один шейдер‑пасс на слой, порядок фиксирован)
| Компонент | Формула | Параметры |
|---|---|---|
| **Lens (бочка/подушка)** | `p = (uv−c)·vec2(aspect,1)`; `r² = dot(p,p)`; `uv_src = c + (uv−c)·(1 + k1·r² + k2·r⁴)/norm`; `norm` подбирается так, чтобы углы оставались в кадре (auto‑overscan) | k1 −0.5…+0.5, k2, центр (можно привязать к треку), «заполнить края»: overscan / зеркало / размытая подложка |
| **Fisheye** | эквидистантная: `θ = r·fov/2`, `uv_src = c + dir·tan(θ)/tan(fov/2)` | fov 60–170°, mix |
| **Bulge / Pinch** | в радиусе R: `s = 1 − (d/R)²`; `uv_src = c + (uv−c)·(1 − amount·s²)`; amount < 0 — pinch | центр (ручная точка / трек), R, amount, мягкость края |
| **Хром. аберрация** | радиальная: каналы сэмплятся с разными `k1_R = k1+ca`, `k1_B = k1−ca`, или сдвиг `R = tex(c+(uv−c)(1+k))`, `B = tex(c+(uv−c)(1−k))` | ca 0–8 px @1080, растёт к краям |
| **Detail / перерезкость** | `Y' = Y + a1·(Y − G_σ1(Y)) + a2·(Y − guided(Y, r))·4Y(1−Y)`; по яркости, до зерна; clamp против ореолов по желанию | a1 0–2.5 (σ1 0.8–1.5 px), clarity a2 0–0.6 (r 24 px), «ореол» on/off |
| **Wave / Heat** | `uv_src = uv + A·vec2(sin(2π(uv.y·f + t·v)), 0)` или noise‑смещение `A·noise2(uv·f, t)` | A, f, v, направление |
| **Twirl** | поворот на угол `θ = amount·(1−d/R)²` вокруг центра | центр, R, amount |
| **Радиальный смаз** | `Σ w_s·tex((uv−c)/(z(1+0.028s))+c)`, сила = `|dz/dt|·shutter` | N=12, центр |

Все сэмплинги — бикубик/Lanczos‑2 (не билинейка), чтобы искажение не мылило. Искажение идёт **до** грейда и Detail (иначе перерезкость «растягивается»).

### 13.2. Ручное управление
- Каждый параметр анимируемый (◆), кривые easing из §8.2, копирование между клипами.
- Центр искажения — клик по монитору или привязка к треку (§10).
- A/B‑шторка «до/после» (клавиша `\`).

## 14. Цветокор (GPU)

### 14.1. Порядок
Декод (YUV→RGB, BT.709 limited) → линеаризация `pow(x, 2.4)` (BT.1886) → exposure и ББ в линейном → контраст в логе вокруг 0.18 → roll‑off светов → CDL/насыщенность/вторичные/split‑toning в display → креативный LUT → Lens & Detail пространственные части → bloom/halation/виньетка → зерно/дизеринг → квантование.

### 14.2. Шейдер первичного грейда (WebGL2)
```glsl
#version 300 es
precision highp float; precision highp sampler3D;
uniform sampler2D uSrc; uniform sampler3D uLut; uniform float uLutN, uLutMix;
uniform vec3 uWB; uniform float uExpo, uContrast, uKnee, uSat, uVib;
uniform vec3 uSlope, uOffset, uPower; uniform vec4 uShadowTint, uHighTint;
uniform vec4 uHue[4]; uniform float uSkinProtect;
in vec2 vUv; out vec4 o;
const vec3 K = vec3(0.2126, 0.7152, 0.0722);
vec3 lin(vec3 c){ return pow(max(c,0.), vec3(2.4)); }  vec3 disp(vec3 c){ return pow(max(c,0.), vec3(1./2.4)); }
vec3 rgb2hsv(vec3 c){ vec4 K4=vec4(0.,-1./3.,2./3.,-1.); vec4 p=mix(vec4(c.bg,K4.wz),vec4(c.gb,K4.xy),step(c.b,c.g));
  vec4 q=mix(vec4(p.xyw,c.r),vec4(c.r,p.yzx),step(p.x,c.r)); float d=q.x-min(q.w,q.y); return vec3(abs(q.z+(q.w-q.y)/(6.*d+1e-6)),d/(q.x+1e-6),q.x); }
void main(){
  vec3 c = lin(texture(uSrc, vUv).rgb) * uWB * exp2(uExpo);
  c = 0.18 * exp2(log2(max(c, 1e-5) / 0.18) * uContrast);
  vec3 k = vec3(uKnee); c = mix(c, k + (1.-k)*(1.-exp(-(c-k)/(1.-k))), step(k, c));
  vec3 d = pow(max(disp(c) * uSlope + uOffset, 0.), uPower);
  vec3 hsv = rgb2hsv(clamp(d,0.,1.)); float Y = dot(d, K);
  float skin = smoothstep(0.10, 0.02, abs(hsv.x - 0.07)) * smoothstep(0.1, 0.3, hsv.y) * uSkinProtect;
  float satMul = uSat * (1. + uVib * (1. - hsv.y));
  for (int i = 0; i < 4; i++) { float dh = abs(fract(hsv.x - uHue[i].x + .5) - .5);
    float w = max(0., cos(min(dh / uHue[i].y, 1.) * 1.5708)); satMul *= 1. + (uHue[i].z - 1.) * w; }
  satMul = mix(satMul, 1. + (satMul - 1.) * 0.35, skin);
  d = Y + (d - Y) * satMul;
  float w = smoothstep(0.05, 0.95, Y);
  d += uShadowTint.rgb * uShadowTint.a * (1. - w) + uHighTint.rgb * uHighTint.a * w;
  vec3 s = (clamp(d,0.,1.) * (uLutN - 1.) + .5) / uLutN;
  d = mix(d, texture(uLut, s).rgb, uLutMix);
  o = vec4(d, 1.);
}
```
`sampler3D` — трилинейная интерполяция; в переходном FFmpeg‑пути ставить `lut3d=interp=trilinear` для совпадения.

### 14.3. Кнопка «Выровнять» (ручная, не ИИ)
По нажатию: 12 кадров региона → перцентили p1/p50/p99 и серый мир по почти нейтральным пикселям → `expo = clamp(log2(0.40/p50), −1, +1)`, ББ ±15%/канал, offset по p1. Значения записываются в ползунки (пользователь видит и правит). Константно на клип; никакого покадрового автоэкспо (даёт пульсацию). По умолчанию не применяется.

### 14.4. Пространственные операции
Clarity (guided filter r=24 px, k 0.2–0.3, маска средних тонов); Bloom (soft‑knee 0.85, 6 уровней dual‑filter, 0.05–0.12) и Halation (веса (1, 0.35, 0.1)); виньетка `1 − 0.18·r^1.6`; RCAS (FSR1, MIT) 0.25–0.4 на выходном разрешении; зерно blue‑noise 64×64 с офсетом `hash(frame)`, амплитуда `0.025·(4Y(1−Y))^0.5`, ≤3% на x264.

### 14.5. Пресеты
`Viral Punch`, `Teal & Orange`, `Night Neon`, `Clean Natural`, `Moody Film`, `B&W Contrast`, `Custom LUT (.cube)`, `TV Acid (legacy)`. Слайдер «Сила» 0–100%. **Viral Punch**: contrast 1.18; knee 0.80; CDL slope (1.02, 1.00, 0.97), offset (−0.010, −0.004, +0.012); sat 1.15; vib 0.25; красные ×1.18, пурпур ×1.12, зелень ×0.92; skinProtect 0.6; тени teal (0, 0.03, 0.05)·0.6, света warm (0.05, 0.02, −0.02)·0.5; clarity 0.25; bloom 0.08; halation 0.04; vignette 0.18; RCAS 0.35; grain 0.025.

### 14.6. Мост на переходный период

Совпадение по построению. `tv_grade.cube` пересобирается этим же способом из собственного пресета (закрывает вопрос происхождения, §19).

### 17.2. Рендер в Electron → x264 (основной путь)
- Финальный кадр упаковывается шейдером в **yuv420p BT.709 limited** с blue‑noise дизерингом ±0.5 LSB: Y‑пасс `(W/4)×H RGBA8`, U/V `(W/8)×(H/2)`; `Cb = 128 + 224·(B'−Y')/1.8556`, `Cr = 128 + 224·(R'−Y')/1.5748`.
- Асинхронный readback: 3 PBO по кругу + `fenceSync`.
- 1080×1920×1.5 = 3 110 400 байт/кадр; при 30 fps рендера ≈ 93 МБ/с по localhost WebSocket; кредиты ≤ 8 неподтверждённых кадров, `{ack:n}` каждые 4.
```python
@app.websocket("/ws/render/{job_id}")
async def ws_render(ws: WebSocket, job_id: str):
    await ws.accept()
    hdr = await ws.receive_json()   # {w,h,fps,frames,audio_wav,out}
    args = ["ffmpeg","-y","-f","rawvideo","-pix_fmt","yuv420p","-s",f"{hdr['w']}x{hdr['h']}","-r",str(hdr['fps']),
            "-color_range","tv","-colorspace","bt709","-color_primaries","bt709","-color_trc","bt709","-i","pipe:0",
            "-i",hdr["audio_wav"],"-map","0:v","-map","1:a",
            "-c:v","libx264","-preset","slow","-crf","16","-tune","film","-profile:v","high","-level","4.2",
            "-x264-params","aq-mode=3:deblock=-1,-1","-g",str(hdr['fps']*2),"-pix_fmt","yuv420p",
            "-colorspace","bt709","-color_primaries","bt709","-color_trc","bt709","-color_range","tv",
            "-c:a","aac","-b:a","320k","-movflags","+faststart","-shortest",hdr["out"]]
    proc = await asyncio.create_subprocess_exec(*args, stdin=asyncio.subprocess.PIPE, stderr=asyncio.subprocess.PIPE)
    n = 0
    try:
        while n < hdr["frames"]:
            proc.stdin.write(await ws.receive_bytes()); await proc.stdin.drain(); n += 1
            if n % 4 == 0: await ws.send_json({"ack": n})
    finally:
        proc.stdin.close(); rc = await proc.wait(); await ws.send_json({"done": rc == 0})
```
Windows: asyncio‑subprocess требует Proactor‑цикла (uvicorn `--reload` может включить Selector) → проверить или писать в `subprocess.Popen` из потока через `asyncio.Queue(maxsize=8)`. Уровень H.264: 8160 MB/кадр × 60 = 489 600 MB/s → **High@4.2** (`avc1.64002A`).
- Аудио собирается сервером до видео в WAV (SFX, `extra_audio`, дакинг) + **двухпроходный** `loudnorm=I=-14:TP=-1:LRA=11` + лимитер; мукс в той же команде.
- «Быстрый» режим: WebCodecs `VideoEncoder` (`avc1.64002A`, 25 Мбит/с, `latencyMode:"quality"`, annexb) → тот же WebSocket → `-c:v copy`.

### 17.3. Качество
Один ресэмплинг (Lanczos‑3/EWA в шейдере); опционально FSR1 EASU+RCAS для кропов < 720 px (MIT, реалтайм). Экспорт 1080×1920@60 (опция 2160×3840), BT.709‑теги, `+faststart`, AAC 320k 48 кГц, −14 LUFS, TP ≤ −1 dBTP.

### 17.4. Переходный экспорт (ASS‑путь до рендерера)
Фаза 0 (§6) + порядок графа H6 + статичные Lens & Detail через FFmpeg (§13.4).
