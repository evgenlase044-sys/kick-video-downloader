# Перепроверка плана по коду (итерация 2)

Дополнение к `docs/PLAN_viral_quality.md`. Проверено по `server.py` (через MCP: сам файл + полный дифф коммита `da71310`, который затронул экспорт, превью и субтитры), `web/editor.js` (дифф), истории коммитов и покадрово по экспорту `Short_jesusavgn_20260926_064127_1.mp4`.

## 1. Главное: твой экспорт собран СТАРОЙ версией кода

В файле видны признаки веток, которые были удалены коммитом `da71310` (26.09, 01:00 UTC). Экспорт сделан в 06:41 по Екатеринбургу (01:41 UTC), то есть уже после этого коммита, но результат соответствует коду ДО него:

| Что видно в видео | Код до `da71310` (сейчас удалён) |
|---|---|
| «ЭТОТ» — зелёное размытое пятно без обводки | ветка Standard Glow: `bord_tag = "\\bord0" if widx % 2 == 0` — каждое чётное слово без обводки, только glow `\blur{wide_b}` + `\1a&H95&` |
| «Д О Н А Т», «С Л О М А Л» вылетают по буквам и налезают друг на друга | ветка «побуквенная печать из центра»: для слов `len(wt) >= 4 and dur_ms >= 500` каждая буква — отдельный Dialogue с `\move(cx → x)` и `\fscx25 → 100` |
| все слова от 5 букв жёлтые | старый `hot = _is_hot_word(wt)` (любое слово длиной ≥ 5), сейчас — одно слово на фразу (`hot_idx`) |

**Вывод:** запущенный у тебя бэкенд не соответствует `main`. Либо сервер (`python server.py`, его запускает `main.js`) не перезапускался после обновления, либо приложение стартует из другой папки/копии. **Шаг 0 любого исправления:** закрыть приложение полностью (включая процесс python), убедиться, что запускается именно эта рабочая копия, и заново экспортировать тот же фрагмент. Часть дефектов (зелёные пятна, разлёт букв) в текущем `main` уже изменена.

## 2. Что подтверждено в текущем `main`

- **Двойной текст (RC1) — остаётся.** `ExportClipItem` принимает `subtitles` (рендерит `build_tv_subtitles_ass`) и `text_items` (рендерит `build_text_elements_ass`) без дедупа. Белая статичная фраза в твоём видео — это текстовый клип «ЭТОТ ДОНАТ СЛОМАЛ СТРИМ» с таймлайна (`text_items`, белый цвет по умолчанию `&H00FFFFFF`, 4 слоя: glow×2 + тень + обводка). Хотфикс H1 обязателен.
- **Посимвольная печать в `build_text_elements_ass` (`anim_in == "type"`) — остаётся** с отдельным `\pos` на букву, метриками из `fontTools` и `\N`, который превращается в букву `N`. H2 в силе.
- **Glow раньше текста (RC3) — частично.** В текущем коде glow-слои Acid используют тот же `pop_tag`, но у Main есть `\fad(15, …)`, а у glow нет, плюс `wide_b = max(8, size*0.14*gk)`. Пятно слабее, но в первые 1–2 кадра всё равно видно. H4 в силе.
- **Грейд (RC6):** `hqdn3d=1.2:1.2:5:5 → lut3d(tetrahedral) → eq(contrast 1.05, sat 1.10) → cas 0.30 → yuv420p` подтверждено. До `da71310` был «пульсирующий» `eq=eval=frame:brightness='0.03+0.035*sin(2*PI*t/0.9)'` и bloom через `lutrgb` — это убрано.
- **FX (RC7):** flash — `blend=all_mode=addition` (раньше был `overlay`), shake — `crop` по синусу + `scale lanczos`. Подтверждено.
- **Дубль `_sfx_maybe_file`**, `_source_has_audio → True` при ошибке, перезапись `fonts/fonts.conf` при старте — подтверждено.

## 3. Поправки к плану

1. **«Мигания композиции» нет.** Это сплит-раскладка: `top_h = out_h * 0.45` (верх 864 px) и низ 1056 px. При пустых `crop_box`/`bg_box` обе полосы режутся из одного кадра, поэтому Telegram оказывается и сверху, и снизу. Решается H5 (автообласти) — отдельного бага с переключением нет.
2. **Громкость и энкодер уже есть.** Экспорт уже делает `loudnorm=I=-14:TP=-1.5:LRA=11` (однопроходный) и `libx264 -preset medium -crf 15 -tune film -x264-params aq-mode=3:aq-strength=0.9:deblock=-1,-1 -g 60 -bf 3`, BT.709-теги, AAC 256k 48 кГц. В плане §10: заменить на **двухпроходный** loudnorm (однопроходный «качает» громкость на коротких клипах), энкодер не трогать. Мыло идёт не от энкодера, а от источника 720p и `hqdn3d`.
3. **Разрешение уже 1080×1920** для любых вертикальных форматов (раньше без TV-грейда было 576×1024). Ок.
4. **Новое поведение верхних видеослоёв (`_export_layered_clip`)**: клип на верхней дорожке без `pip`/`track_path` теперь накладывается **на весь кадр** (`scale … force_original_aspect_ratio=increase, crop`, `enable=between(t, …)`). Если на дорожку «Оверлей / Вебка» положить обычный клип, он полностью перекроет сплит на время своей длительности. В UI это нужно явно показывать (иконка «на весь кадр / PiP»), иначе результат выглядит как случайная смена картинки.
5. **Кусочки WYSIWYG уже есть:** в `editor.js` есть композитное превью 9:16 («TV 9:16 composite preview: EXACTLY like the export will look», `renderPip`, `appendFxDivs`, `pipForClip`), а в `server.py` — эндпоинт `preview_frame` (FFmpeg-кадр со сплитом/кропом). Проблема в том, что они включаются только в режиме 9:16, а переключатель по умолчанию стоит на `16:9` и не связан с выбранным форматом Shorts. H7 можно сделать за час: при выборе Shorts-формата переключать монитор в 9:16 и по паузе подтягивать кадр с `preview_frame` поверх (точный кадр экспорта с грейдом).
6. **`fmt_ass_time` с привязкой к 60 fps** добавлен в `da71310`, но ASS всё равно хранит сотые, поэтому точность ±10 мс (не кадр). На пословные субтитры практически не влияет, пункт RC10 понижаю до «мелочь».

## 4. Что не удалось прочитать через MCP

GitHub отдаёт `server.py` (≈3500 строк) с обрезкой примерно на строке 2300, а патч первого коммита для такого большого файла GitHub не формирует. Поэтому средняя часть `export_clip_pack` (построение сплита из `crop_box`/`bg_box`, порядок наложения `subtitles` / `text_items` / FX) видна только по фрагментам диффа. Выводы выше этим не опровергаются, но для 100% покрытия этой функции нужен сам файл целиком.
